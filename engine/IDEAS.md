# Idea Inbox

Daily **idea sweeps** land here when the backlog runs dry. Each sweep appends one
`## YYYY-MM-DD` section with two groups: **Ideas** (dreamed up) and **Opportunities**
(grounded in a read of the actual repo). Bullets are plain `-`, never `- [ ]`, so the
backlog parser never mistakes an idea for a buildable task.

**Triage (Wolf, by hand):**
- **Queue it** → copy the bullet into `engine/BACKLOG.md` as a `- [ ]` task, then delete
  it from here.
- **Reject it** → move the bullet to `engine/IDEAS-rejected.md`; the next sweep reads that
  file and won't re-propose it.
- **Ignore it** → leave it here; it stays as standing context and won't be resurfaced.

### Ideas (dreamed up)

- **Build it twice** — run one backlog line through two independent cycles on parallel branches and publish the diff between the two implementations. Nobody has an honest picture of how much an agentic build varies run-to-run on the *same* instruction; the loop is the only place that can measure it cheaply, and the answer ("the machine wrote a different thing both times, here they are") is the kind of finding a lab exists to produce. Record each failed run (task, phase it died in, error) as a durable artifact and publish it. A public lab that only ships its successes is publishing an advertisement; the failures are the differentiated content.
- **Ask the lab** — client-only retrieval over the *bodies* of the Lab corpus, not just title+summary. 44 entries and growing weekly, and the only way in is `filterLabItems`' substring match over two fields. A build-time JSON index plus BM25 in the browser stays inside the no-server constraint and makes the archive usable as a reference instead of a scroll.

Extract them as a documented starter ("run your own always-on lab: backlog in, PRs out, path-guarded auto-merge") with the whatupwolf-specific bits parameterised. The interesting part is that the extraction itself is a cycle the machine can run on itself.
- **Listen to the lab** — a zero-key page that reads a Lab entry aloud with `speechSynthesis` (the machinery is already proven in `public/tools/voice-loop.html`), with the entry's `plain` reading as the spoken text since the technical one is unreadable out loud. - `/video` is a nav link to a placeholder. `src/content/video/sample-demo.md` is the collection's only entry: title ends "(demo)", `summary` literally begins "Placeholder entry —", and `embed` is `https://www.youtube.com/watch?v=placeholder` — a dead URL. `src/components/Nav.astro:6` puts Video in the chrome of every page, and `src/pages/video.astro:24` makes the title an outbound link to that URL, so the whole route is one broken link presented as published work (the level variants at `:7-9` were even backfilled for it). - The cycle runner can wedge on a pushed branch that has no PR. `engine/publish.mjs:41-42` pushes and *then* opens the PR; if `gh pr create` fails after a successful push (auth blip, rate limit), the remote branch exists with a commit and no PR. Next tick `branchHasPr` (`engine/run-cycle.mjs:108`) says "no PR", the item is re-picked, `checkout -B` (`:281`) resets the branch to main, and the push is rejected non-fast-forward — the cycle fails, recovers, and repeats forever on the same item. `engine/run-experiment.mjs:220` already solved exactly this with `uniqueBranchName(base, parseRemoteBranches(ls-remote …))`; `run-cycle.mjs` imports neither helper.
- Post-failure recovery runs *outside* the single-instance lock. In both runners the lock is released in `main()`'s `finally` (`engine/run-cycle.mjs:245-249`) and `recoverToMain()` is called from the outer `catch` at the bottom of the file (`:385-391`, same shape at `engine/run-experiment.mjs`'s tail). So the one moment the tree is guaranteed half-finished, `git checkout -f main` + `git clean -fd` execute unlocked — a second run can take the lock and start its own git work mid-recovery, and `clean -fd` will delete its untracked files. That is precisely the corruption the lock was built for. Move the recovery inside the locked scope.
- `shortTitle` collapses an annotated backlog line to its status prefix. It takes the lead clause before the first `: ` or spaced dash (`engine/lib.mjs:41`), so `branchForItem` on the two annotated lines in `engine/BACKLOG.md` (`:58`, `:69`) returns `lab/built` and `lab/superseded-by-tier-9-pr-30` (verifiable: `node -e "import('./engine/lib.mjs').then(L=>console.log(L.branchForItem('(BUILT — PR #22 open) Close the …')))"`). Inert while those items are `[x]` — but `BACKLOG.md:55-57` *instructs* Wolf to annotate items with that exact prefix, and the skip guard keys off the line's current text, so annotating an item silently changes its branch identity: the "already built into a PR" check stops matching, and a rebuild would commit under the title "built". Strip a leading parenthetical before taking the lead clause.
- The guard workflow interpolates changed filenames into a shell string. `.github/workflows/guard.yml:73` ends the allowlist loop with `<<< '${{ steps.files.outputs.list }}'` — a GitHub expression pasted inside single quotes in a `run:` block, so a path containing a single quote closes the string and the remainder is shell, in the job that decides whether a PR auto-merges. Low exposure today (the file names come from our own machine, and a fork PR's token is read-only), but the fix is mechanical: pass the list through `env:` and read `"$LIST"` instead of splicing it into the script.

- No nav item highlights on an entry page. `src/components/Nav.astro:14` computes `path` from the full pathname and `:26` marks a link active only on exact equality, so on `/lab/<id>/` (`path` = `/lab/<id>`) nothing matches `/lab` — the same for `/writing/<id>/`. ## 2026-07-29

### Ideas (dreamed up)

- **A gardener cycle — the loop's only permitted diff is deletion.** Every cycle so far has been additive: 42 lab entries, 20 backlog tiers, six 33–75 KB single-file tools, dead carve-outs like `class="prose"` and the `/video` placeholder. A repo that only grows is one an agent eventually can't hold in context, and no human is going to volunteer for a deletion PR. Make it a recurring kind whose verify gate *rejects a diff with net additions* — the constraint is the whole idea, and it's the one shape of work the machine is better placed to do than Wolf.
- **Teach the monitor to look.** `engine/probes/site-health.mjs` reads status codes, headers, cert dates and link targets — every one of which stays green while the site renders as unstyled text or a tool page loads blank. A screenshot pass (one headless browser on the box) diffed against the last run would catch the entire class of failure the current probe is structurally blind to. Costs a real dependency, which is exactly the trade to argue in public.
- **Generated share cards, authored from the *plain* reading.** The lab has three authored depths of every title and ships the technical one to every surface, including the zero social previews it currently emits. Build-time per-entry SVG→PNG cards rendering the plain title in the paper theme would make the content model pay for itself at the exact moment an entry leaves the site — and it's the only place the plain reading is unambiguously the right one, because nobody hovers a link to read file names.
- **Show the visitor what a turn cost them.** Four BYO-key tools spend the *visitor's* tokens and none of them says how much; the API already returns a `usage` block on every response. A small honest meter — tokens in/out, running session estimate in USD, per model — costs nothing to render and is the sort of thing no other BYO-key demo bothers with. Distinct from pricing the engine's own cycles: this is the reader's bill, not ours.

### Opportunities (grounded in a repo read)

- The visitor pastes their API key once per tool, and "forget key" only forgets one of them. The four BYO-key tools each define their own store: `genui.anthropic-key` (`public/tools/generative-ui.html:331`), `branchchat.anthropic-key` (`branching-chat.html:367`), `memins.anthropic-key` (`memory-inspector.html:360`), `voiceloop.anthropic-key` (`voice-loop.html:597`) — four independent entries under the same `whatupwolf.com` origin, plus four more `*.model` keys. Two consequences, one friction and one trust: moving between tools means re-pasting the key, and a visitor who clicks "Forget key" in the Generative UI Canvas leaves three copies of that key sitting in `localStorage` while the page tells them it's cleared. One shared store name (`whatupwolf.anthropic-key`) fixes both; the clear button should wipe the whole namespace.
- Every machine-written lab timestamp loses its timezone on the way to disk. `renderLabEntry` (`engine/lib.mjs:135`) does `date.toISOString().slice(0, 16)`, which cuts the string at `YYYY-MM-DDTHH:mm` and drops the `Z` — so a UTC instant is stored as a naive local time. `z.coerce.date()` then re-reads it as *build-machine local*, and `src/components/LabEntry.astro:33`, `src/pages/lab/[...id].astro:16` and `src/pages/lab/index.astro:19` all call `.toISOString()` on the result again. In CI (UTC) the round-trip is identity, so nothing is visibly wrong; on Wolf's CDT box every `npm run dev` / `npm run build` renders all 42 entries five hours off. `hello-lab.md`'s hand-written `date: 2026-06-27T10:00` has the same shape. Fix is one character — and note it moves the displayed time on every existing entry, so decide which reading is the intended one first.
- The guard's auto-merge zone contains the sanitizer that constrains the machine's own output — and that sanitizer's tests. `.github/workflows/guard.yml:48` allowlists `src/lib/*`, which is not just pure helpers: `src/lib/sanitize.core.mjs` is the fail-closed secret scan every monitor report passes through (`publicEntryFromReport`, `engine/lib.mjs`), and `src/lib/sanitize.test.ts` — the only thing asserting it still fails closed — sits in the same directory. So one machine-authored PR can weaken the leak guard *and* relax the test that would have caught it, and merge itself on green CI. `src/lib/tech-level.ts`, `feed.ts` and `lab-filter.ts` are live site runtime in the same zone. Live only under `AUTONOMY_TIER == 'B'`, and nothing in the repo tests the allowlist itself. Carve `sanitize*` out, or hold `src/lib/` gated.
- `/lab` ships the same 35 KB twice. `src/pages/lab/index.astro:57` mounts `<LabFilter items={log} client:load />`, so Astro renders every log entry to HTML *and* serialises the identical items into the island's `props` attribute: measured on the current `dist/lab/index.html`, 111,644 bytes total of which the props blob alone is 35,208 — a third of the page, before compression, duplicating what's already above it. It grows one entry per cycle with no pagination and no cap anywhere in the chain (`partitionLab` caps `reads`, never `log`), and `client:load` hydrates a below-the-fold filter on first paint. `client:visible` is a one-word change; trimming the serialised projection or paginating the log is the real fix.
- The RSS feed silently picks the technical reading, on both fields. `src/lib/feed.ts:26-31` declares `LabData` without `summaryLevels`, and `buildFeedItems` sets `description` from `e.data.summary` and prefixes the raw `title` with its type — the technical source in both cases — even though 34 of the 42 entries carry authored lighter variants. A feed reader has no level switch, so this is the one surface where the site must *choose* a depth on the visitor's behalf, and it currently chooses by omission: subscribers get titles like "Add an in-code single-instance lock to engine/run-cycle.mjs AND…", precisely the wall of file names `src/content.config.ts:25-27` says the translation exists to prevent. Pick a level on purpose (plain or aware reads best in a feed) and thread the variants through `FeedEntry`.
