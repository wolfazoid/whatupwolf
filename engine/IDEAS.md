# Idea Inbox

Daily **idea sweeps** land here when the backlog runs dry. Each sweep appends one
`## YYYY-MM-DD` section with two groups: **Ideas** (dreamed up) and **Opportunities**
(grounded in a read of the actual repo). Bullets are plain `-`, never `- [ ]`, so the
backlog parser never mistakes an idea for a buildable task.

**Triage (Wolf, by hand):**
- **Queue it** → copy the bullet into `engine/BACKLOG.md` as a `- [ ]` task, then delete
  it from here.
- **Reject it** → move the bullet to `engine/IDEAS-rejected.md`; the next sweep reads that
  file and won't re-propose it.
- **Ignore it** → leave it here; it stays as standing context and won't be resurfaced.

## 2026-07-23

### Ideas (dreamed up)
- **Loop retrospective** — a recurring experiment (`kind: digest`) that reads the last N merged cycle PRs + `engine/cycle.log` and publishes what the machine got wrong, what the verify gate caught, and the flagged-vs-clean rate. The lab's one unrepeatable asset is its own operating history; nobody else can write that post.
- **`/engine` status page** — a build-time page rendered from git history: cycles run, PRs merged, flagged rate, days on. Turns the "always-on machine" claim from copy into a number a visitor can check.
- **Provenance link per Lab entry** — capture the PR number in frontmatter at publish time and render "built by cycle #NN ↗" on the entry. Proof-of-work becomes verifiable instead of asserted; costs one field in `renderLabEntry`.
- **Context-budget visualizer** — client-only tool: paste a system prompt / conversation, get a block-by-block breakdown of what's eating the window (approximate tokenizer, no key, no server). Everyone building agents guesses at this; nobody sees it.
- **Idea-inbox auto-ranking** — a light sweep mode that re-reads the standing bullets in this file and re-emits them ranked by value × feasibility, so triage is a sorted list rather than an archaeology dig once the inbox is 40 bullets deep.

## 2026-07-24

### Ideas (dreamed up)
- **Adversarial self-review before the PR opens** — after the machine finishes a cycle, the runner invokes a second, independent `claude -p` whose only job is to read `git diff main...HEAD` against the backlog line and answer "does this do what was asked, and what's wrong with it?", appended to the PR body. Today the only independent judgement in the loop is `npm test` + `npm run check` (`engine/run-cycle.mjs:308-322`), which says nothing about whether the work matches the task.
- **Cycle replay** — an interactive page that walks a visitor through one real cycle end to end: the backlog line, the diff, the verify gate, the PR. The lab's unrepeatable asset is that every build is already recorded; a replay makes "an always-on machine builds this site" something you watch rather than read.
- **Agent-legible lab** — publish `/llms.txt` plus a structured JSON feed of the Lab and Tools collections, then treat "who reads this site" as an open question: increasingly the answer is another agent. Cheap to build (both derive from existing collections) and an honest experiment in writing for a non-human reader.
- **Prompt-injection dojo** — a client-only, zero-key tool in the reasoning-trace mould: the visitor plays the defender while injected instructions arrive in "tool output", and scoring shows how often they'd have let an agent be steered. AI literacy for the failure mode people actually hit with agents, and it needs no server.
- **A recurring `audit` experiment kind** — a third pipeline alongside `digest`/`monitor` in `engine/experiments/registry.mjs` that adversarially re-tests our own shipped BYO-key tools (key never leaves the parent, iframes stay `allow-scripts`-only, `connect-src` unchanged) and files findings. The security posture of `public/tools/*.html` was reviewed once, at build time, and never since.

- `class="prose"` on the Lab entry body is a no-op. `src/pages/lab/[...id].astro:52` styles the write-up with ad-hoc `[&_h2]`/`[&_p]`/`[&_code]` variants plus a `prose` class that matches nothing: `src/styles/global.css` has zero `prose` rules and `@tailwindcss/typography` is not a dependency. With preflight on, markdown bullets lose their markers and inline links lose their colour — `src/content/lab/2026-07-18-agent-weekly.md` alone has 7 list/link lines rendering as flat grey text.
- Lab search can't find the featured entries. `src/pages/lab/index.astro:57` passes only `log` into `<LabFilter>`, while `partitionLab()` has already pulled every tool and recent read into `FeaturedStrip` — which has no query awareness. So a `draft: true` briefing builds and deploys at its real URL, just unlinked. Latent right now (no draft entry exists), but the whole review gate — `draftForType('briefing')` in `engine/lib.mjs:162` — assumes a draft is not published.
- Tag chips leak into the plain reading level. `src/components/LabEntry.astro:50` and `src/pages/lab/[...id].astro:32` deliberately mark their tag rows `data-variant="technical aware"` so `#engine`-style jargon disappears at the plain level, but the equivalent rows in `src/pages/tools/index.astro:27` and the stack chips in `src/pages/work.astro:65` carry no `data-variant` — and `src/styles/global.css:48-51` only hides elements that have one.
- Nothing tests the five shipped tools. `src/lib/` and `engine/` are well covered by vitest, but `public/tools/*.html` (cooking, generative-ui, reasoning-trace, branching-chat, memory-inspector) has no test at all, so the verify gate that guards every cycle cannot notice a tool regressing. ### Opportunities (grounded in a repo read)
- There is no 404 page. `src/pages/` has no `404.astro`, so the build emits no `dist/404.html`, and `wrangler.jsonc` sets no `assets.not_found_handling` — every bad URL gets Cloudflare's bare default with no nav, no theme, and no route back into the site. A mistyped `/tools/…html` deep-link (the tools are linked by raw filename from `src/content/tools/*.md`) is the most likely way a visitor finds it.
- The guard allowlist is wider than the constitution says it is. `.github/workflows/guard.yml` matches `src/content/lab/*|engine/*|src/lib/*` as a shell `case` pattern, where `*` spans `/` — so **every** file under `engine/` auto-merges except the single `engine/CYCLE.md` carve-out. Meanwhile `engine/CYCLE.md`'s "Gated paths" section tells the machine the allowlist is `BACKLOG.md`, `run-cycle.mjs`, `lib.mjs` (+tests), `README.md`. In practice `engine/IDEATE.md` (this sweep's own manual), `engine/publish.mjs`, `engine/run-experiment.mjs`, the `engine/experiments/*.md` research prompts, and the cron scripts `engine/run-*.sh` are all auto-mergeable. Narrow the guard or correct the doc — right now the two disagree about where the trust boundary sits.
- The experiment runner has no verify gate. `engine/run-cycle.mjs:308-322` re-runs `npm test` + `npm run check` and uses `resolveStatus` to override a rosy self-report to `flagged`; `engine/run-experiment.mjs` imports no `resolveStatus`, defines no `gate()`, and publishes its Lab entry and PR straight from the machine's own status (lines 288-327). A digest or monitor whose body breaks the build opens an unmarked PR that only CI catches. Same spine, one of the two rails missing.
- Every entry the runner writes is untranslated, and the gap grows one per cycle. `renderLabEntry` (`engine/lib.mjs:134-151`) emits `title`/`summary` only — never `titleLevels`/`summaryLevels` — and `parseCycleReport` (`engine/lib.mjs:269`) gives the machine nowhere to author them. 34 of the 40 files in `src/content/lab/` carry level variants (backfilled by Tier 11); the 6 that don't are exactly the entries written since. A plain-level visitor gets titles like "Add an in-code single-instance lock to engine/run-cycle.mjs AND…" — precisely what the comment at `src/content.config.ts:25-27` says the lab's title translation exists to prevent. The machine knows what it built; ask it for the two lighter readings in the report.
- The monitor's private-report archive path can collide. `engine/run-experiment.mjs:256` writes the private half to `engine/reports/${day}${suffix}.json` — keyed by date only, not by experiment name (`suffix` only counts same-name branch collisions). A second monitor in `engine/experiments/registry.mjs` would silently overwrite site-health's archive on any day both ran. Latent while one monitor exists; the fix is one interpolation.
- `flagged` renders identically to `done`. `src/components/LabEntry.astro:41`, `src/components/FeaturedStrip.astro:43` and `src/pages/lab/[...id].astro:23` all print `status: {status}` as the same muted mono text. One of the 40 lab entries is `status: flagged`. The loop's entire honesty rail is that a failing gate marks the work — and then the feed presents that work exactly like work that passed.

### Opportunities (grounded in a repo read)
- Every date the engine stamps is UTC, and the box is not. `engine/run-cycle.mjs:167` (`runIdleIdeation`) and `:339` (the Lab entry) both use `new Date().toISOString().slice(0, 10)`, as does `engine/run-experiment.mjs`. The box runs CDT (UTC−5), so any cycle after 19:00 local stamps **tomorrow's** date on the entry filename, the entry frontmatter, the branch name, and the idea-section heading. Live instance: this sweep was handed `2026-07-26` while the wall clock read Sat 25 Jul 19:01 CDT. Consequence beyond cosmetics — a future-dated entry sorts above genuinely newer ones in `src/pages/index.astro:9` and `src/pages/lab/index.astro`, and `latestIdeaDate` (`engine/lib.mjs:311`) keys its once-a-day guard off the same shifted day.
- Four of the six tools pin a superseded model. `public/tools/generative-ui.html`, `branching-chat.html`, `memory-inspector.html` and `voice-loop.html` each hardcode a picker of `claude-sonnet-5` / `claude-opus-4-8` / `claude-haiku-4-5` — and `claude-opus-4-8` is a generation behind Opus 5. Nothing in the repo notices vendor drift: the model ids and `anthropic-version` live in static HTML that no test reads and no experiment re-checks, so each tool silently ages from the day it merges. The pins are the fix; a recurring freshness check is what stops it recurring.
- The site-health monitor's route list is frozen at the site's June shape. `engine/probes/site-health.mjs:10` is `KEY_ROUTES = ['/', '/lab', '/work', '/writing', '/rss.xml']`. Since it was written the site gained `/tools`, `/now`, `/video`, per-post `/writing/<id>` routes (PR #50), and six `public/tools/*.html` pages. The monitor reports the site healthy while never fetching the six artifacts most likely to break — a tool 404ing after a bad deploy is exactly the failure it exists to catch.
- No `robots.txt` and no sitemap. `public/` contains only `_headers` and `tools/`; `astro.config.mjs` sets `site: 'https://whatupwolf.com'` but adds no `@astrojs/sitemap`, so nothing tells a crawler the 50+ built routes exist. Sharpest version of the point: our own prober is a good citizen and fetches `/robots.txt` before crawling (`engine/probes/site-health.mjs`) — against whatupwolf.com that request 404s. Both files are cheap; the sitemap is one integration line given `site` is already set.
- The CSP is in observation mode with nobody observing. `public/_headers:24` ships `Content-Security-Policy-Report-Only` with no `report-uri` and no `report-to`, so violations exist only in the console of whoever happens to have devtools open — which is nobody. The file's own promotion criterion (`public/_headers:15-17`) is "watch the console on / and /lab across a few deploys, then rename the header," a manual step that was never scheduled and has not run since 2026-07-18. Either wire a real report sink (needs an endpoint → an app-subdomain forcing case) or make the promotion check a step in the site-health monitor, which already reads `headers:{csp,hsts,xcto}` for presence and could assert enforcement.
- The level switch remembers a choice the visitor never made. `src/components/LevelSwitch.astro:59` calls `apply(root.dataset.level ?? …)` on every page load to correct `aria-pressed`, and `apply()` writes `localStorage.setItem(STORAGE_KEY, next)` unconditionally (`:45`). So the first page view pins every visitor to `technical` in storage, even though `src/lib/tech-level.ts:41-43` documents the contract as "the site keeps its current depth for anyone who never touches the switch; choosing a lighter reading is **opt-in** and remembered." Harmless today because the stored value equals `DEFAULT_LEVEL` — it becomes a real bug the day the default changes, since every prior visitor stays pinned to the old one. Split the persist out of `apply()`, or only write from the click handler.
