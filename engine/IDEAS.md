# Idea Inbox

Daily **idea sweeps** land here when the backlog runs dry. Each sweep appends one
`## YYYY-MM-DD` section with two groups: **Ideas** (dreamed up) and **Opportunities**
(grounded in a read of the actual repo). Bullets are plain `-`, never `- [ ]`, so the
backlog parser never mistakes an idea for a buildable task.

**Triage (Wolf, by hand):**
- **Queue it** → copy the bullet into `engine/BACKLOG.md` as a `- [ ]` task, then delete
  it from here.
- **Reject it** → move the bullet to `engine/IDEAS-rejected.md`; the next sweep reads that
  file and won't re-propose it.
- **Ignore it** → leave it here; it stays as standing context and won't be resurfaced.

Nobody has an honest picture of how much an agentic build varies run-to-run on the *same* instruction; the loop is the only place that can measure it cheaply, and the answer ("the machine wrote a different thing both times, here they are") is the kind of finding a lab exists to produce. A public lab that only ships its successes is publishing an advertisement; the failures are the differentiated content.

The interesting part is that the extraction itself is a cycle the machine can run on itself.

Next tick `branchHasPr` (`engine/run-cycle.mjs:108`) says "no PR", the item is re-picked, `checkout -B` (`:281`) resets the branch to main, and the push is rejected non-fast-forward — the cycle fails, recovers, and repeats forever on the same item. `engine/run-experiment.mjs:220` already solved exactly this with `uniqueBranchName(base, parseRemoteBranches(ls-remote …))`; `run-cycle.mjs` imports neither helper.
- Post-failure recovery runs *outside* the single-instance lock. In both runners the lock is released in `main()`'s `finally` (`engine/run-cycle.mjs:245-249`) and `recoverToMain()` is called from the outer `catch` at the bottom of the file (`:385-391`, same shape at `engine/run-experiment.mjs`'s tail). - `shortTitle` collapses an annotated backlog line to its status prefix. Inert while those items are `[x]` — but `BACKLOG.md:55-57` *instructs* Wolf to annotate items with that exact prefix, and the skip guard keys off the line's current text, so annotating an item silently changes its branch identity: the "already built into a PR" check stops matching, and a rebuild would commit under the title "built". Strip a leading parenthetical before taking the lead clause.
- The guard workflow interpolates changed filenames into a shell string. `.github/workflows/guard.yml:73` ends the allowlist loop with `<<< '${{ steps.files.outputs.list }}'` — a GitHub expression pasted inside single quotes in a `run:` block, so a path containing a single quote closes the string and the remainder is shell, in the job that decides whether a PR auto-merges. Low exposure today (the file names come from our own machine, and a fork PR's token is read-only), but the fix is mechanical: pass the list through `env:` and read `"$LIST"` instead of splicing it into the script.
